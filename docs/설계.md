# 채용공고 추천 CLI 설계안

## 1. 프로젝트 개요

이 프로젝트는 `https://inthiswork.com/it`에 올라온 IT 채용공고를 수집하고, 사용자의 입력 조건에 맞는 공고를 추천해주는 **JavaScript 기반 CLI 실행 파일 프로그램**이다.

사용자는 실행 파일을 실행한 뒤 터미널에서 원하는 조건을 입력한다. 프로그램은 inthiswork의 IT 채용공고 목록을 조회하고, 아직 DB에 저장되지 않은 신규 공고만 상세 페이지까지 들어가서 본문을 수집한다. 이미 저장된 공고는 다시 상세 페이지를 조회하지 않는다.

수집된 공고는 SQLite DB 파일에 누적 저장된다. 프로그램을 다시 실행해도 DB를 초기화하지 않고 기존 DB 파일을 그대로 사용한다.

초기 버전은 키워드 기반 점수화 방식으로 추천 공고를 정렬한다. 추후에는 공고 본문과 사용자 입력을 벡터로 변환하여 벡터 유사도 기반 검색 기능을 추가할 예정이다.

## 2. 핵심 요구사항

### 2.0 MVP 성공 기준

초기 구현은 실행 파일 패키징보다 `npm start`로 동작하는 CLI 검증을 우선한다.

MVP가 완료된 것으로 보는 기준:

```text
- npm start 실행 시 터미널 입력을 받을 수 있음
- 빈 DB 상태에서 실행하면 data/job-finder.db를 자동 생성함
- 재실행해도 기존 DB 데이터를 삭제하지 않음
- 목록 페이지는 매 실행마다 조회함
- 상세 페이지는 DB에 없는 신규 URL만 조회함
- 신규 공고를 raw_text와 함께 SQLite에 저장함
- 저장된 공고 전체를 대상으로 키워드 점수를 계산함
- 점수 높은 순서로 상위 10개 공고를 출력함
- 검색 이력을 search_history에 저장함
```

실행 파일 빌드는 MVP 이후 안정화 단계에서 검증한다.

### 2.1 실행 방식

* JavaScript / Node.js로 구현한다.
* 최종적으로 실행 파일 형태로 만든다.
* 사용자가 실행 파일을 실행하면 터미널 인터페이스가 열린다.
* 사용자는 터미널에 원하는 채용 조건을 입력한다.
* 프로그램은 입력 조건을 기준으로 적합한 공고를 찾아 출력한다.

예상 실행 흐름:

```bash
job-finder.exe
```

터미널 출력 예시:

```text
채용공고 추천 CLI
====================

원하는 조건을 입력하세요:
> 백엔드 신입 Spring Node.js AWS

몇 페이지까지 새 공고를 확인할까요? 기본값 3:
> 3

새 공고 확인 중...
새로 저장한 공고: 12개
이미 저장된 공고: 38개

추천 공고
====================

[1] 회사명｜Backend Engineer
점수: 95
매칭: Backend, Node.js, 신입
주의: -
URL: https://inthiswork.com/archives/...
```

## 3. DB 정책

### 3.1 DB 선택

* SQLite 사용
* 별도 DB 서버를 사용하지 않는다.
* 실행 파일이 SQLite DB 파일을 자동 생성하고 관리한다.

정확한 의미:

```text
실행 파일 내부에 DB를 직접 포함하는 것이 아니다.
실행 파일이 실행될 때 로컬 경로에 SQLite DB 파일을 만들고,
이후 같은 DB 파일을 계속 재사용한다.
```

### 3.2 DB 파일 생성 정책

MVP의 DB 파일 위치는 다음으로 고정한다.

```text
process.cwd()/data/job-finder.db
```

즉, `npm start`를 실행한 프로젝트 루트 기준으로 `data/job-finder.db`가 생성된다.
실행 파일 배포 안정화 이후에는 사용자 홈 디렉터리 기반 경로로 옮길 수 있지만, MVP 구현에서는 경로 정책을 바꾸지 않는다.

프로그램 실행 시 다음 순서로 동작한다.

```text
1. data 폴더 확인
2. 없으면 생성
3. data/job-finder.db 파일 확인
4. 없으면 새 DB 파일 생성
5. 있으면 기존 DB 파일 그대로 사용
6. CREATE TABLE IF NOT EXISTS 실행
7. 기존 데이터 삭제 금지
8. PRAGMA foreign_keys = ON 실행
```

중요:

```text
프로그램 실행 시 DB 초기화 금지
기존 DB 파일이 있으면 그대로 사용
공고 데이터 누적 저장
```

DB 연결은 프로그램 종료 직전에 닫는다.
전역 오류가 발생해도 가능한 경우 `db.close()`를 호출한다.

### 3.3 DB 저장 대상

DB에 저장하는 데이터:

```text
- 채용공고 제목
- 회사명
- 공고 URL
- 공고 상세 본문 텍스트
- 출처
- 저장 시각
- 검색 이력
- 추후 벡터 임베딩
```

DB에 저장하지 않아도 되는 데이터:

```text
- HTML 원본 전체
- 이미지
- 첨부 파일
- 외부 사이트의 스타일 정보
```

## 4. 공고 수집 정책

### 4.1 목록 페이지 조회

목록 페이지는 실행할 때마다 조회한다.

대상 URL:

```text
1페이지: https://inthiswork.com/it
2페이지: https://inthiswork.com/it?paged1=2
3페이지: https://inthiswork.com/it?paged1=3
...
```

사용자가 입력한 `maxPage` 값만큼 조회한다.

예:

```text
maxPage = 3

조회 대상:
- /it
- /it?paged1=2
- /it?paged1=3
```

목록에서 추출한 URL은 항상 절대 URL로 정규화해서 저장한다.

```text
허용:
https://inthiswork.com/archives/12345

정규화 대상:
/archives/12345
```

초기 selector 정책:

```text
1. 메인 콘텐츠 영역 안의 공고 링크를 우선 추출한다.
2. 메인 영역 selector가 실패하면 a[href*="/archives/"] 필터를 fallback으로 사용한다.
3. 페이지네이션 이후의 "오늘 핫한 공고", 커리어 키워드, 최신 댓글 영역은 목록 공고로 저장하지 않는다.
4. 동일 URL이 한 페이지에 여러 번 나오면 첫 번째만 사용한다.
```

이유:

```text
inthiswork 목록 페이지에는 실제 공고 목록 외에도 사이드바/추천/댓글 링크가 함께 노출될 수 있다.
단순히 모든 a[href*="/archives/"]를 저장하면 추천 대상이 아닌 링크가 섞일 수 있다.
```

### 4.2 상세 페이지 조회

상세 페이지는 무조건 조회하지 않는다.

목록 페이지에서 공고 URL을 추출한 뒤, DB에 해당 URL이 이미 있는지 확인한다.

```text
목록 페이지에서 공고 URL 추출
  ↓
DB에 URL 존재 여부 확인
  ↓
이미 있으면 상세 페이지 조회하지 않음
  ↓
없으면 상세 페이지 조회
  ↓
본문 텍스트 추출
  ↓
DB 저장
```

이 정책의 목적:

```text
- 같은 공고를 반복 수집하지 않음
- 사이트 요청 수 감소
- 실행 속도 개선
- DB 중복 저장 방지
```

### 4.3 공고 갱신 가정

이 프로젝트에서는 다음과 같이 가정한다.

```text
한 번 저장된 공고는 수정되지 않는다.
```

따라서 TTL 캐시는 사용하지 않는다.
이미 저장된 공고는 다시 상세 페이지를 조회하지 않는다.

다만 추후 개선 기능으로 다음 옵션을 추가할 수 있다.

```text
--refresh <url>
특정 공고 강제 재조회

--refresh-all
전체 공고 강제 재조회

--recent 7
최근 7일 저장 공고만 검색
```

## 5. 중복 저장 방지 정책

공고의 중복 기준은 URL이다.

DB 테이블에서 `url` 컬럼에 `UNIQUE` 제약조건을 건다.

```sql
url TEXT NOT NULL UNIQUE
```

저장 시에는 `INSERT OR IGNORE`를 사용한다.

```sql
INSERT OR IGNORE INTO job_postings (...)
VALUES (...);
```

따라서 중복 방지는 두 단계로 처리한다.

```text
1. 애플리케이션 레벨
   - 저장 전 existsByUrl(url) 확인

2. DB 레벨
   - url UNIQUE
   - INSERT OR IGNORE
```

이중으로 막는 이유:

```text
코드 실수나 동시 실행 상황에서도 중복 저장 가능성을 줄이기 위해서
```

## 7. 기술 스택

### 7.1 기본 구현

```text
Language: JavaScript

CLI 입력: readline

HTML 파싱: cheerio
```

### 7.2 주의사항

`better-sqlite3`는 native module이다.
따라서 `pkg`로 실행 파일을 만들 때 추가 설정이 필요할 수 있다.

초기 개발은 `better-sqlite3`로 진행한다.

이유:

```text
- 동기식 API라 CLI 프로그램에 적합
- 코드가 단순함
- 성능이 좋음
- SQLite 사용 방식이 직관적임
```

패키징에서 문제가 생기면 다음 대안을 검토한다.

```text
1. pkg 설정 수정
2. nexe 사용
3. sqlite3 라이브러리로 변경
4. sql.js 사용
```

## 9. DB 스키마

### 9.1 job_postings

채용공고 원문 정보를 저장한다.

```sql
CREATE TABLE IF NOT EXISTS job_postings (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  source TEXT NOT NULL,
  title TEXT NOT NULL,
  company TEXT,
  url TEXT NOT NULL UNIQUE,
  raw_text TEXT NOT NULL,
  created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP
);
```

추가 인덱스:

```sql
CREATE INDEX IF NOT EXISTS idx_job_postings_created_at
ON job_postings(created_at);

CREATE INDEX IF NOT EXISTS idx_search_history_created_at
ON search_history(created_at);
```

컬럼 설명:

```text
id
- 내부 식별자

source
- 공고 출처
- 예: inthiswork

title
- 공고 제목

company
- 회사명
- 제목에서 추출 가능하면 저장
- 추출 실패 시 빈 문자열 허용

url
- 공고 상세 페이지 URL
- 중복 방지 기준
- UNIQUE 필수

raw_text
- 상세 페이지에서 추출한 본문 텍스트
- 검색과 점수화의 핵심 데이터

created_at
- DB에 저장된 시각
```

### 9.2 search_history

사용자 검색 이력을 저장한다.

```sql
CREATE TABLE IF NOT EXISTS search_history (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  query TEXT NOT NULL,
  result_count INTEGER NOT NULL,
  created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP
);
```

목적:

```text
- 사용자가 어떤 조건으로 검색했는지 기록
- 나중에 자주 검색하는 조건 분석 가능
- 추후 추천 프로필 자동화에 활용 가능
```

### 9.3 job_embeddings

추후 벡터 검색을 위해 사용할 테이블이다.

초기 버전에서는 생성만 해두고 사용하지 않아도 된다.

```sql
CREATE TABLE IF NOT EXISTS job_embeddings (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  job_posting_id INTEGER NOT NULL UNIQUE,
  embedding_model TEXT NOT NULL,
  embedding TEXT NOT NULL,
  created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (job_posting_id) REFERENCES job_postings(id)
);
```

컬럼 설명:

```text
job_posting_id
- job_postings.id 참조

embedding_model
- 벡터 생성에 사용한 모델명
- 예: text-embedding-3-small, local-model 등

embedding
- 벡터 배열을 JSON 문자열로 저장
- 예: [0.123, -0.456, ...]

created_at
- 벡터 생성 시각
```

### 9.4 DB 초기화와 마이그레이션 원칙

MVP에서는 별도 마이그레이션 도구를 도입하지 않는다.

구현 원칙:

```text
- CREATE TABLE IF NOT EXISTS만 사용
- CREATE INDEX IF NOT EXISTS만 사용
- DROP TABLE 금지
- 기존 job_postings 데이터 DELETE 금지
- PRAGMA foreign_keys = ON 설정
```

스키마 변경이 필요한 시점에는 `schema_migrations` 테이블을 추가하는 방식으로 별도 설계한다.

## 11. 모듈별 상세 설계

## 11.1 database.js

역할:

```text
- data 폴더 생성
- SQLite DB 파일 연결
- 테이블 생성
- 기존 DB 파일이 있으면 그대로 사용
```

구현 핵심:

```js
const fs = require("fs");
const path = require("path");
const Database = require("better-sqlite3");

function openDatabase() {
  const dataDir = path.join(process.cwd(), "data");

  if (!fs.existsSync(dataDir)) {
    fs.mkdirSync(dataDir, { recursive: true });
  }

  const dbPath = path.join(dataDir, "job-finder.db");
  const db = new Database(dbPath);

  db.pragma("foreign_keys = ON");
  createTables(db);

  return db;
}

function createTables(db) {
  db.exec(`
    CREATE TABLE IF NOT EXISTS job_postings (
      id INTEGER PRIMARY KEY AUTOINCREMENT,
      source TEXT NOT NULL,
      title TEXT NOT NULL,
      company TEXT,
      url TEXT NOT NULL UNIQUE,
      raw_text TEXT NOT NULL,
      created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP
    );

    CREATE TABLE IF NOT EXISTS search_history (
      id INTEGER PRIMARY KEY AUTOINCREMENT,
      query TEXT NOT NULL,
      result_count INTEGER NOT NULL,
      created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP
    );

    CREATE TABLE IF NOT EXISTS job_embeddings (
      id INTEGER PRIMARY KEY AUTOINCREMENT,
      job_posting_id INTEGER NOT NULL UNIQUE,
      embedding_model TEXT NOT NULL,
      embedding TEXT NOT NULL,
      created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
      FOREIGN KEY (job_posting_id) REFERENCES job_postings(id)
    );

    CREATE INDEX IF NOT EXISTS idx_job_postings_created_at
    ON job_postings(created_at);

    CREATE INDEX IF NOT EXISTS idx_search_history_created_at
    ON search_history(created_at);
  `);
}

module.exports = {
  openDatabase,
};
```

## 11.2 jobRepository.js

역할:

```text
- 공고 존재 여부 확인
- 공고 저장
- 전체 공고 조회
- 검색 이력 저장
```

필수 메서드:

```text
existsByUrl(url)
save(job)
findAll()
saveSearchHistory(query, resultCount)
```

`save(job)`는 저장 여부를 알 수 있도록 `{ inserted: boolean }`을 반환한다.
`INSERT OR IGNORE` 결과의 `changes`가 1이면 신규 저장, 0이면 중복으로 무시된 것이다.

구현 예시:

```js
class JobRepository {
  constructor(db) {
    this.db = db;

    this.existsByUrlStmt = db.prepare(`
      SELECT EXISTS(
        SELECT 1 FROM job_postings WHERE url = ?
      ) AS exists_flag
    `);

    this.saveStmt = db.prepare(`
      INSERT OR IGNORE INTO job_postings
      (source, title, company, url, raw_text)
      VALUES (?, ?, ?, ?, ?)
    `);

    this.findAllStmt = db.prepare(`
      SELECT id, source, title, company, url, raw_text, created_at
      FROM job_postings
      ORDER BY id DESC
    `);

    this.saveSearchHistoryStmt = db.prepare(`
      INSERT INTO search_history (query, result_count)
      VALUES (?, ?)
    `);
  }

  existsByUrl(url) {
    const row = this.existsByUrlStmt.get(url);
    return row.exists_flag === 1;
  }

  save(job) {
    const result = this.saveStmt.run(
      job.source,
      job.title,
      job.company,
      job.url,
      job.rawText
    );

    return {
      inserted: result.changes === 1,
    };
  }

  findAll() {
    return this.findAllStmt.all();
  }

  saveSearchHistory(query, resultCount) {
    this.saveSearchHistoryStmt.run(query, resultCount);
  }
}

module.exports = {
  JobRepository,
};
```

```js
const axios = require("axios");
const cheerio = require("cheerio");

const BASE_URL = "https://inthiswork.com";

function buildListUrl(page) {
  if (page === 1) {
    return `${BASE_URL}/it`;
  }

  return `${BASE_URL}/it?paged1=${page}`;
}

function normalizeUrl(href) {
  return new URL(href, BASE_URL).toString();
}

async function fetchJobLinks(page) {
  const url = buildListUrl(page);

  const response = await axios.get(url, {
    headers: {
      "User-Agent": "Mozilla/5.0",
    },
    timeout: 10000,
  });

  const $ = cheerio.load(response.data);
  const jobs = [];
  const seen = new Set();
  const candidates = $("main a, article a").length > 0
    ? $("main a, article a")
    : $("a");

  candidates.each((_, element) => {
    const title = $(element).text().replace(/\s+/g, " ").trim();
    const href = $(element).attr("href");

    if (!href) return;
    if (!href.includes("/archives/")) return;
    if (!title) return;

    const normalizedUrl = normalizeUrl(href);

    if (seen.has(normalizedUrl)) return;

    seen.add(normalizedUrl);

    jobs.push({
      title,
      url: normalizedUrl,
    });
  });

  return jobs;
}

module.exports = {
  buildListUrl,
  fetchJobLinks,
};
```

## 11.5 jobSearchService.js

역할:

```text
- 목록 크롤러와 상세 크롤러 조합
- DB 중복 확인
- 신규 공고만 저장
```

필수 함수:

```text
syncNewJobs(jobRepository, maxPage)
```

동작:

```text
1. 1페이지부터 maxPage까지 목록 조회
2. 각 공고 URL에 대해 DB 존재 여부 확인
3. 존재하면 skippedCount 증가
4. 존재하지 않으면 상세 조회
5. 본문 저장
6. savedCount 증가
7. 요청 간 sleep 적용
```

구현 예시:

```js
const { fetchJobLinks } = require("../crawler/listCrawler");
const { fetchJobDetail } = require("../crawler/detailCrawler");

function extractCompany(title) {
  if (!title.includes("｜")) {
    return "";
  }

  return title.split("｜")[0].trim();
}

async function syncNewJobs(jobRepository, maxPage) {
  let savedCount = 0;
  let skippedCount = 0;
  let failedCount = 0;

  for (let page = 1; page <= maxPage; page++) {
    let links;

    try {
      links = await fetchJobLinks(page);
    } catch (error) {
      failedCount++;
      continue;
    }

    for (const link of links) {
      if (jobRepository.existsByUrl(link.url)) {
        skippedCount++;
        continue;
      }

      try {
        const detail = await fetchJobDetail(link.url);

        jobRepository.save({
          source: "inthiswork",
          title: link.title,
          company: extractCompany(link.title),
          url: link.url,
          rawText: detail.rawText,
        });

        savedCount++;
      } catch (error) {
        failedCount++;
      }

      await sleep(500);
    }
  }

  return {
    savedCount,
    skippedCount,
    failedCount,
  };
}

function sleep(ms) {
  return new Promise((resolve) => setTimeout(resolve, ms));
}

module.exports = {
  syncNewJobs,
};
```

주의:

```text
한 공고 조회 실패가 전체 프로그램 실패로 이어지지 않게 한다.
개별 공고 실패는 failedCount만 증가시키고 계속 진행한다.
```

## 11.6 keywordScorer.js

역할:

```text
- 저장된 공고와 사용자 입력을 비교
- 키워드 기반 점수 계산
- 적합 공고 필터링
- 점수 높은 순 정렬
```

중요한 점수화 원칙:

```text
사용자 query 문자열 자체를 공고 텍스트에 붙여서 점수화하지 않는다.
query에 포함된 키워드를 모든 공고에 가점하면 모든 결과가 같은 기본 점수를 받는 오류가 생긴다.
MVP에서는 query에 포함된 긍정 키워드 규칙만 활성화하고, 공고의 title/raw_text에 실제로 등장한 경우에만 가점한다.
query에서 알려진 긍정 키워드를 하나도 찾지 못하면 기본 positiveRules 전체를 사용한다.
부정 키워드는 query와 무관하게 공고의 title/raw_text에 등장하면 감점한다.
```

기본 점수 정책:

```text
긍정 키워드:
- 신입
- 경력 무관
- 주니어
- 백엔드
- Backend
- Back-end
- 서버
- Java
- Spring
- Spring Boot
- Node.js
- NestJS
- SQL
- MySQL
- AWS
- Docker

부정 키워드:
- 3년 이상
- 5년 이상
- 시니어
- 리드
- 프론트엔드

- 영업

```

구현 예시:

```js
const positiveRules = [
  { keyword: "신입", score: 30 },
  { keyword: "경력 무관", score: 30 },
  { keyword: "주니어", score: 20 },
  { keyword: "백엔드", score: 30 },
  { keyword: "Backend", score: 30 },
  { keyword: "Back-end", score: 30 },
  { keyword: "서버", score: 20 },
  { keyword: "Java", score: 20 },
  { keyword: "Spring", score: 25 },
  { keyword: "Spring Boot", score: 30 },
  { keyword: "Node.js", score: 20 },
  { keyword: "NestJS", score: 20 },
  { keyword: "SQL", score: 10 },
  { keyword: "MySQL", score: 10 },
  { keyword: "AWS", score: 10 },
  { keyword: "Docker", score: 10 },
];

const negativeRules = [
  { keyword: "3년 이상", score: -40 },
  { keyword: "5년 이상", score: -70 },
  { keyword: "시니어", score: -70 },
  { keyword: "리드", score: -50 },
  { keyword: "프론트엔드", score: -30 },
  { keyword: "마케팅", score: -50 },
  { keyword: "영업", score: -50 },
  { keyword: "디자인", score: -50 },
];

function resolveActivePositiveRules(query) {
  const queryText = query.toLowerCase();
  const activeRules = positiveRules.filter((rule) =>
    queryText.includes(rule.keyword.toLowerCase())
  );

  return activeRules.length > 0 ? activeRules : positiveRules;
}

function scoreJob(job, query) {
  const text = `${job.title} ${job.raw_text}`.toLowerCase();
  const activePositiveRules = resolveActivePositiveRules(query);

  let score = 0;
  const matchedKeywords = [];
  const warningKeywords = [];

  for (const rule of activePositiveRules) {
    if (text.includes(rule.keyword.toLowerCase())) {
      score += rule.score;
      matchedKeywords.push(rule.keyword);
    }
  }

  for (const rule of negativeRules) {
    if (text.includes(rule.keyword.toLowerCase())) {
      score += rule.score;
      warningKeywords.push(rule.keyword);
    }
  }

  return {
    id: job.id,
    title: job.title,
    company: job.company,
    url: job.url,
    score,
    matchedKeywords,
    warningKeywords,
  };
}

function findMatchedJobs(jobs, query, minScore = 50) {
  return jobs
    .map((job) => scoreJob(job, query))
    .filter((result) => result.score >= minScore)
    .sort((a, b) => b.score - a.score);
}

module.exports = {
  findMatchedJobs,
};
```

주의:

```text
초기 버전은 단순 키워드 기반이다.
"3년 이상 우대"와 "3년 이상 필수"를 구분하지 못할 수 있다.
추후 본문 섹션 분리 또는 LLM 판단으로 개선 가능하다.
```

## 13. 실행 파일 패키징 주의사항

`better-sqlite3`는 native module이므로 `pkg`에서 문제가 발생할 수 있다.

문제가 생길 경우 확인할 것:

```text
1. better-sqlite3 native binary가 포함되었는지
2. pkg assets 설정이 필요한지
3. Node 버전과 better-sqlite3 버전 호환 여부
4. Windows 환경에서 빌드하는지
```

## 14. 벡터 검색 확장 설계

추후에는 키워드 검색만으로 부족하므로 벡터 검색 기능을 추가한다.

### 14.1 현재 방식의 한계

키워드 기반 검색은 다음 문제를 가진다.

```text
- "서버 개발"과 "백엔드 개발"을 다르게 볼 수 있음
- "REST API 개발 경험"이 백엔드 적합 신호라는 것을 약하게 판단함
- "클라우드 환경 운영"이 백엔드/인프라 적합성과 연결되는 것을 잘 모름
- "3년 이상 우대"와 "3년 이상 필수"를 구분하기 어려움
```

### 14.2 벡터 검색 목표

```text
공고 본문을 벡터로 변환
사용자 입력 조건도 벡터로 변환
두 벡터의 cosine similarity 계산
의미적으로 가까운 공고를 우선 추천
```

예:

```text
사용자 입력:
"신입 백엔드, Spring Boot, Node.js, DB 경험을 살릴 수 있는 공고"

공고 본문:
"REST API 개발, 서버 사이드 로직 구현, MySQL 기반 서비스 개발 경험 우대"

키워드가 완전히 일치하지 않아도 의미적으로 관련성이 높으면 추천
```

### 14.3 벡터 저장 방식

초기에는 별도 벡터 DB를 도입하지 않고 SQLite에 JSON 문자열로 저장한다.

```sql
CREATE TABLE IF NOT EXISTS job_embeddings (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  job_posting_id INTEGER NOT NULL UNIQUE,
  embedding_model TEXT NOT NULL,
  embedding TEXT NOT NULL,
  created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (job_posting_id) REFERENCES job_postings(id)
);
```

예:

```json
[0.0123, -0.221, 0.541, 0.034]
```

### 14.4 벡터 검색 파일 구조

```text
src/vector/
├─ embeddingService.js
├─ vectorRepository.js
└─ similarity.js
```

### 14.5 similarity.js

```js
function cosineSimilarity(a, b) {
  if (a.length !== b.length) {
    throw new Error("벡터 차원이 다릅니다.");
  }

  let dot = 0;
  let normA = 0;
  let normB = 0;

  for (let i = 0; i < a.length; i++) {
    dot += a[i] * b[i];
    normA += a[i] * a[i];
    normB += b[i] * b[i];
  }

  if (normA === 0 || normB === 0) {
    return 0;
  }

  return dot / (Math.sqrt(normA) * Math.sqrt(normB));
}

module.exports = {
  cosineSimilarity,
};
```

### 14.6 최종 추천 점수

추후에는 키워드 점수와 벡터 유사도를 합친다.

예:

```text
최종 점수 = 키워드 점수 * 0.4 + 벡터 유사도 점수 * 0.6
```

구체 예시:

```js
finalScore = keywordScore * 0.4 + vectorScore * 100 * 0.6;
```

## 15. 에러 처리 정책

### 15.1 목록 페이지 조회 실패

```text
특정 목록 페이지 조회 실패 시:
- 프로그램 전체 종료하지 않음

```

### 15.2 상세 페이지 조회 실패

```text
특정 공고 상세 조회 실패 시:
- 해당 공고 저장하지 않음
- failedCount 증가
- 다음 공고 계속 처리
```

### 15.3 DB 저장 실패

```text
DB 저장 실패 시:
- 중복 URL이면 무시 가능
- 그 외 오류는 로그 출력
- 프로그램은 가능한 계속 진행
```

### 15.4 사용자 입력 오류

```text
maxPage가 숫자가 아니면 기본값 3 사용
maxPage가 1보다 작으면 기본값 3 사용
maxPage가 10보다 크면 10으로 제한
query가 비어 있으면 기본 검색 조건 사용
```

기본 검색 조건 예:

```text
백엔드 신입 Spring Node.js
```

MVP 입력 기본값:

```text
DEFAULT_QUERY = "백엔드 신입 Spring Node.js"
DEFAULT_MAX_PAGE = 3
MAX_PAGE_LIMIT = 10
```

## 17. MVP 테스트 기준

초기 구현은 자동 테스트와 수동 실행 검증을 함께 둔다.

### 17.1 DB 테스트

```text
- DB 파일이 없을 때 data/job-finder.db 생성
- CREATE TABLE IF NOT EXISTS로 테이블 생성
- 기존 job_postings 데이터 삭제 없음
- 같은 URL 저장 시 중복 row 생성 없음
- save(job)가 신규 저장 여부를 inserted boolean으로 반환
- search_history 저장 가능
```

### 17.2 크롤러 테스트

```text
- buildListUrl(1)은 https://inthiswork.com/it 반환
- buildListUrl(2)는 https://inthiswork.com/it?paged1=2 반환
- 상대 URL /archives/123을 절대 URL로 정규화
- /archives/가 아닌 링크 제외
- 같은 URL 중복 제거
- 상세 본문 텍스트 공백 정규화
```

### 17.3 서비스 테스트

```text
- 이미 저장된 URL은 상세 조회하지 않음
- 신규 URL만 상세 조회 후 저장
- 목록 페이지 조회 실패 시 다음 페이지 계속 처리
- 상세 페이지 조회 실패 시 다음 공고 계속 처리
- savedCount, skippedCount, failedCount를 정확히 반환
```

### 17.4 점수화 테스트

```text
- query에 포함된 긍정 키워드 규칙만 활성화
- 활성화된 긍정 키워드가 공고 title/raw_text에 있을 때만 가점
- query에 알려진 긍정 키워드가 없으면 positiveRules 전체 사용
- 공고 title/raw_text에 있는 부정 키워드 감점
- query에만 있는 키워드는 모든 공고에 가점하지 않음
- minScore 미만 결과 제외
- score 내림차순 정렬
```

### 17.5 CLI 수동 검증

```text
- npm start로 프로그램 실행
- 빈 query 입력 시 기본 검색 조건 사용
- 잘못된 maxPage 입력 시 기본값 3 사용
- 첫 실행 후 data/job-finder.db 생성 확인
- 두 번째 실행에서 기존 URL 상세 재조회가 줄어드는지 확인
- 추천 결과가 없으면 "조건에 맞는 공고가 없습니다." 출력
```
