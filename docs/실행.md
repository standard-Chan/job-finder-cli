# 실행 메모

## 현재 실행 방식

개발 실행은 다음 명령을 사용한다.

```bash
npm start
```

현재 CLI 입력 순서는 다음과 같다.

```text
1. 원하는 조건 입력
2. 검색 방식 선택
   - 1 또는 빈 입력: 추천/의미 기반
   - 2, keyword, 키워드: 키워드 반드시 포함
3. 조회할 페이지 수 입력
```

예:

```text
원하는 조건을 입력하세요: Kafka
검색 방식을 선택하세요. 1=추천/의미 기반(기본), 2=키워드 반드시 포함: 2
몇 페이지까지 새 공고를 확인할까요? 기본값 3: 1
```

## 검증 명령

Windows에서 실행 중이면 Windows 터미널에서 테스트한다.

```bat
npm test
```

WSL에서 실행 중이면 WSL 터미널에서 테스트한다.

```bash
npm test
```

중요한 기준:

```text
npm install과 npm start/npm test는 같은 OS 환경에서 실행한다.
```

## 진행률 출력

페이지 진행은 줄 단위로 출력한다.

```text
[페이지 1/1] 목록 조회 중...
[페이지 1/1] 공고 40개 확인 시작
```

공고 진행은 같은 줄을 갱신하는 로딩바로 출력한다.

```text
[페이지 1/1] [==========          ] 20/40 NAVER Cloud｜Security 분야 채용 ...
```

주의:

```text
자동화 캡처 로그나 파이프 실행 출력에서는 carriage return(\r)이 누적되어 여러 줄처럼 보일 수 있다.
실제 TTY 터미널에서는 현재 줄을 지우고 다시 쓰는 방식으로 한 줄 갱신된다.
공고명이 터미널 폭보다 길면 말줄임표로 잘린다.
```

## Windows와 WSL node_modules 주의

이 프로젝트는 SQLite 라이브러리로 `better-sqlite3`를 사용한다.
`better-sqlite3`는 native module이라 설치한 OS에 맞는 바이너리를 `node_modules`에 만든다.

따라서 같은 프로젝트 폴더를 Windows와 WSL에서 번갈아 쓰는 경우 `node_modules`를 공유하면 안 된다.

Windows에서 실행할 때 다음 오류가 나면 Linux/WSL용 바이너리가 설치된 상태다.

```text
better_sqlite3.node is not a valid Win32 application
```

Windows 터미널에서 다시 설치한다.

```bat
rmdir /s /q node_modules
npm install
npm start
```

WSL에서 실행할 때 Windows용 바이너리가 설치되어 있으면 반대로 다시 설치한다.

```bash
rm -rf node_modules
npm install
npm start
```

실행 환경 하나를 정해서 `npm install`과 `npm start`를 같은 환경에서 실행하는 것이 가장 안전하다.
