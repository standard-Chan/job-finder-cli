# 검색 고도화 설계안

## Summary

- 의미 기반 검색은 `sqlite-vec` + `@huggingface/transformers` + `Xenova/multilingual-e5-small`로 구현한다.
- FTS5는 이번 범위에서 도입하지 않는다. 120건 규모에서는 속도 목적이 약하고, 매칭 키워드 표시는 기존처럼 문자열 검사로 처리한다.
- 검색 결과는 "점수" 대신 유사도 수준과 근거를 보여준다: 접수기간, 매칭 키워드, 의미 매칭, 주의 키워드.
- 접수 종료 공고와 접수기간을 알 수 없는 공고는 검색 결과에서 제외한다. 단, `채용시까지` / `상시채용`은 접수 가능 공고로 포함한다.

## Key Changes

- DB에 검색 필터용 메타데이터를 추가한다.
  - `job_postings`에 `deadline_text`, `deadline_date`, `deadline_kind`, `career_type` 또는 `career_tags`를 추가한다.
  - `deadline_kind`: `date`, `open_ended`, `unknown`.
  - 검색 대상은 `deadline_kind = 'open_ended'` 또는 `deadline_date >= 오늘(Asia/Seoul)`만 포함한다.
- `sqlite-vec`용 가상 테이블을 추가한다.
  - 예: `job_embedding_vec(job_posting_id integer primary key, embedding float[384] distance_metric=cosine)`.
  - 기존 `job_embeddings` 테이블은 모델명, 생성시각, 본문 해시 같은 메타데이터 저장용으로 유지/확장한다.
- 임베딩 생성은 신규 공고 저장 직후 수행한다.
  - 모델: `Xenova/multilingual-e5-small`.
  - 문서 임베딩 입력은 `passage: ${title}\n${raw_text}`.
  - 검색어 임베딩 입력은 `query: ${query}`.
  - Transformers.js는 CommonJS 코드에서 동적 import로 로드한다.
- 검색 흐름을 분리한다.
  - 수집: 목록/상세 크롤링 -> 접수기간/경력 태그 추출 -> DB 저장 -> 임베딩 생성 -> sqlite-vec 저장.
  - 검색: 사용자 조건 정규화 -> 유효 공고 필터 -> 의미 검색 -> 키워드 근거 계산 -> 결과 출력.
- CLI 입력을 확장한다.
  - 경력 조건: `1=신입/인턴(기본), 2=경력, 3=전체`.
  - 다중 검색 조건: `1=OR(기본), 2=AND`.
  - 검색 방식은 기존처럼 의미 기반 기본, 키워드 필수 포함 모드는 유지한다.
- 결과 출력 형식을 바꾼다.
  - `점수:` 제거.
  - `유사도: 높음/보통/낮음` 또는 `의미 매칭: 높음`처럼 표시.
  - `접수기간:`은 항상 출력한다.
  - `매칭:`에는 substring 기반 키워드와 쿼리 토큰 근거를 출력한다.

## Test Plan

- 접수기간 파서 테스트
  - `2026.07.31까지`, `~ 2026년 7월 31일`, `채용시까지`, `상시채용`을 올바르게 분류한다.
  - 종료일이 오늘 이전이면 검색 대상에서 제외한다.
  - 기간을 못 찾으면 제외한다.
- 경력 필터 테스트
  - 기본값은 신입/인턴이다.
  - 신입/인턴, 경력, 전체 선택에 따라 결과 포함 여부가 달라진다.
- 다중 검색 테스트
  - OR 모드는 `Kafka` 또는 `대규모 데이터 처리` 중 하나에 가까운 공고를 포함한다.
  - AND 모드는 모든 검색 의도에 대한 매칭 근거가 있는 공고만 포함한다.
- 벡터 저장소 테스트
  - sqlite-vec extension 로드 후 `vec_version()` 확인.
  - 384차원 벡터 저장과 KNN 조회가 동작한다.
  - 이미 임베딩이 있는 공고는 중복 생성하지 않는다.
- CLI 출력 테스트
  - 결과에 접수기간이 항상 포함된다.
  - 원점수 대신 유사도 수준과 매칭 근거가 출력된다.
- 검증은 같은 OS에서 `npm install` 후 `npm test`로 수행한다. 현재 WSL에서는 Windows용 `better-sqlite3` 바이너리 때문에 재설치가 필요하다.

## Assumptions

- 로컬 모델은 "추론이 로컬에서 돈다"는 의미로 정의한다. 최초 모델/wasm 다운로드는 필요할 수 있고, 이후 캐시된 모델을 사용한다.
- 실행 파일 패키징(`pkg`)에서 Transformers.js 모델과 wasm 번들링은 이번 검색 고도화의 필수 범위에서 제외한다. 우선 `npm start` 기준 동작을 완성한다.
- sqlite-vec Node 사용은 공식 문서의 `sqliteVec.load(db)` 방식과 `vec0` KNN 쿼리 방식을 따른다.

  - https://npm.io/package/%40huggingface/transformers
